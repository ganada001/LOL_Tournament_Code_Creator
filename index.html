현재 운영 구조

프로그램은 기능을 과하게 늘리기보다 Riot Production 심사에서 문제가 될 수 있는 키 노출, 임의 API 호출, 잘못된 라우팅, 중복 요청 위험을 줄이는 방향으로 구성했습니다.

데스크톱 앱

운영자는 프리셋 목록 또는 수동 생성 화면에서 대회 코드를 발급합니다. 앱 설정에는 Riot API 키와 콜백 URL 입력칸을 두지 않습니다.

보안 백엔드

인증된 운영자 요청만 받아 Riot Tournament API에 전달합니다. 허용된 작업은 공급자 등록, 토너먼트 생성, 코드 발급으로 제한하고, 라이브 콜백 검증용 metadata를 서버에서 서명합니다.

외부 전송

발급된 코드는 운영자가 등록한 Discord HTTPS 웹훅으로만 전송합니다. 웹훅 주소는 프리셋별로 관리하며 형식 검증을 거칩니다.

화면 구성

대회 운영 중 빠르게 확인해야 하는 정보가 먼저 보이도록 메인 화면, 설정, 수동 생성, 프리셋 관리를 분리했습니다.

운영 시작 순서

일반 운영자는 서버 키를 다루지 않습니다. 배포된 앱을 실행한 뒤 운영자 계정으로 인증하고, 테스트 환경에서 공급자를 등록한 뒤 코드를 발급합니다.

  1. 프로그램을 실행하고 설정 창을 엽니다.
  2. 운영자 계정으로 로그인합니다.
  3. 승인 전에는 테스트 API 사용을 유지합니다.
  4. 라이엇 토너먼트 라우팅은 기본 검증값을 사용하고, Riot 안내가 있을 때만 변경합니다.
  5. 공급자 ID를 등록한 뒤 프리셋 또는 수동 생성으로 토너먼트 코드를 발급합니다.

Riot 심사 대응 포인트

Riot 공식 문서의 Security, Tournament API Best Practices, Routing Values 기준을 운영 리스크 관점에서 반영했습니다.

Security

Riot API 키는 데스크톱 코드, 로컬 설정, 배포 바이너리에 포함하지 않습니다. 서버 secret으로만 보관하고, 운영자 인증 후 제한된 작업만 실행합니다.

Tournament API

공급자 등록, 토너먼트 생성, 코드 발급 순서를 유지합니다. Stub API를 기본 테스트 환경으로 두고, live API에서는 서명된 metadata로 callback을 검증합니다. 429 또는 재시도성 오류가 발생하면 반복 발급을 중단합니다.

Routing Values

토너먼트 API 라우팅은 Riot 지역 라우팅 값인 americas, asia, europe, sea만 허용합니다. 공급자 지역 KR과 API 호스트 라우팅은 별도로 관리합니다.

백엔드 설정 기준

서버 운영자는 아래 값을 보안 백엔드 secret으로 관리합니다. 일반 운영자 화면에는 이 값들을 직접 입력하는 칸을 노출하지 않습니다.

  • RIOT_API_KEY: 승인 전 Development key, 승인 후 Production key로 교체합니다.
  • RIOT_CALLBACK_URL: 공급자 등록 시 Riot에 전달할 서버 콜백 URL입니다. Live callback은 Riot의 포트, TLD, 인증서 제한을 만족하는 URL로 검증합니다.
  • RIOT_CALLBACK_SECRET: 토너먼트 코드 metadata 서명과 Riot callback 검증에 사용하는 서버 secret입니다.
  • ALLOWED_OPERATOR_EMAILS: 앱 사용을 허용할 운영자 이메일 목록입니다.
  • 데스크톱 앱에는 public client 설정과 운영자 세션만 사용하며, service-role key는 포함하지 않습니다.

자주 묻는 질문

왜 공급자를 등록하나요?

Riot Tournament API에서 공급자는 대회를 주최하는 주체를 식별하는 값입니다. 토너먼트와 코드는 이 공급자 ID를 기준으로 발급됩니다.

승인 전에도 테스트할 수 있나요?

네. Stub API를 사용하면 실제 라이브 서버용 코드가 아니라 테스트용 응답으로 발급 흐름을 검증할 수 있습니다.

Production 승인 후 무엇이 바뀌나요?

앱을 다시 설계하지 않고 서버 secret의 Riot 키를 Production key로 교체합니다. Riot 안내에 따라 라우팅 값도 설정 화면에서 변경할 수 있습니다.
